## 車端仍要完成的接點

| 項目 | 需要提供／實作的內容 | 本次介面如何處理 |
| --- | --- | --- |
| 方案啟用 | 核對當時車端原檔、備份、啟用對應包與 PID；處理快取及不存在的舊檔，讀回實際已載入方案與固定值。依當輪授權決定是否重啟車控 | 只保存選擇，不修改車端、不聲稱載入成功 |
| 持續行駛 | `orin_continuous` 與能力回報，兩層控制 deadline 真正為空，保留相機／路徑／UART／急停等本地保護 | 不呼叫舊 start，不退回限時模式 |
| 本場保存 | Orin 持久化場次 ID、run 片段、控制設定快照、最後保存點、暫停與重啟紀錄；獨立於網頁 | 現階段只有筆電選擇與觀測保存，不假冒場次 |
| 路段接續 | 按 Claude 回覆 2 的白名單，在 Orin 重建 CurveMap、DashRoute、交叉窗口與 TrackPos；區分原地、搬車、MCU 重啟；第一圈／下坡後路線與 generation 要在車端核對 | 保存語意位置，不傳內部 idx／狀態；不承諾彎中或下坡中原地接續 |
| 準備／放行 | 明確分離不出動力的準備與動力放行；確認準備中的回正動作與授權，紅燈期間不可沿用目前一呼叫就開始的 start | 讀取方案完全不呼叫車端 prepare |
| 旗子計時 | 車端 `FLAG_CROSS_EST` 或其他真實過線來源；同圈去重、順序核對、移車／接續不補圈、時間來自同一 Orin 時基；上次／本圈／有效圈數／未完整圈明確分欄 | 不用瀏覽器輪詢推算圈時；目前不提供假的跑動計時 |
| 紅綠燈 | 中控事件格式、場次歸屬、事件有效期、斷線處理與車端等待／放行狀態 | 只保存啟用選擇 |
| 前車停等 | 偵測模型與類別、距離來源／單位／可信度；約 3 m 自動繼續的遲滯／連續確認、目標消失和感測失效策略 | 選項停用，沒有虛構距離 |
| 完整觀測接口 | 車端當格圖＋seq＋擷取時間＋路段位置一併回覆；明確 live、paused、stale；實際方案 ID、場次 ID、控制板狀態與故障排除碼 | 暫用原疊圖與有上限的紀錄讀取，兩者不保證同影格 |

這些接點不是「只要回報一個版本號就自動開放」。後續要完成對應命令／回覆、實際生效核對及必要的受限驗證，再解除開始／接續停用。
