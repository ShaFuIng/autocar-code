### A3.2 拆成待發／放行【提案】

**名稱：** 現有 `/api/pid/prepare` 與 `live_pid.prepare()` 是**載入模型預覽**，不碰車。07 新階段建議叫 **「待發（arm_hold）」**，不要再用 prepare。

- **待發** ＝ 現有 start 的第 1～5 步全部做完（解鎖、回正、建 run），但 live_pid 帶 `hold=True`：每格送 `target_us=中心、pwm=0`（`manual_drive` 中 `pwm=0` → `hard_zero=True` → 兩輪 0，見 `_run` 中 `if hard_zero:right=left=0`）。這條路徑原本就存在（起跑回正段就是這樣做）。
- **放行** ＝ 把 `hold` 改成 False，**同時重新建立 PID 控制器與時間基準**（積分、微分、`start_t`、速度排程），避免等待期間累積。路線物件已在待發時建立、而且在等待期間不移動，不必重建。
- **等待期間仍有效的保護**（不用另外寫）：`live_pid.check_safety()` 的影像過期；`manual_drive._check()` 的 PID 輸入中斷（等待時迴圈照樣每格送 pwm 0，所以不會誤觸）、UART、相機；`_run()` 的 generation／MCU 狀態改變（急停、故障 → `AUTHORIZATION_CHANGED`）；韌體 500 ms 指令逾時。
- **讓舊的放行失效：** 放行要帶待發時發的 `token`（uuid）。live_pid 只在「目前 run 存在、`run.token==token`、`state=='holding'`、manual run 的 generation 未變」時接受；任何停止、故障或急停都會結束 run，舊 token 自然失效。
- **去重與回覆遺失：** 放行是等冪的，同一個 token 第二次只回傳既有結果（`released_at`），不再動作。回覆遺失時查 `/api/pid/status` 的 `run.ops07={token,state,released_at}`，**不要重送**。
- 綠燈輪詢執行緒在 Orin（`ops07_runtime.py`），看到「本次待發先 0 後 1」就呼叫同一個放行函式，走相同的 token 檢查。

### A5.1 狀態語意【已核對】
