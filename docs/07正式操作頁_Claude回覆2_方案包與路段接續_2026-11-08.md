## 1. 優先項 1：持續行駛全鏈路（已核對）

### 1.1 目前有時限的地方（三層）

| 層 | 位置 | 行為 |
| --- | --- | --- |
| 筆電頁面 | `laptop_workbench/pid-live.js` 開始按鈕 | 要求 `seconds` ≥ 1 的有限數；舊車端還有 20 秒上限檢查（`custom_duration_version`） |
| 筆電轉送 | `laptop_workbench/server.py` 約 450 行 | 轉送 `execution_mode`；`orin_timed` 要求車端 `autonomous_pid_version` ≥ 1 |
| Orin live_pid | `start()` 驗證 `seconds`；`run['deadline']`；`check_safety()` 每 50 ms 檢查，到期 → `PID_DURATION_COMPLETE`；status 的 `remaining_s` | **主要時限** |
| Orin manual_drive | `start(_pid=True)` 再驗證一次 `seconds`，自己也存 `run['deadline']`；`_check()` 到期 → `PID_DURATION_COMPLETE` | **第二層時限**，只改 live_pid 不夠 |
| 韌體 | 沒有任務時限 | — |

### 1.2 必須保留的本地保護（不是任務時限）

| 保護 | 位置 | 門檻 |
| --- | --- | --- |
| 影像過期 `PID_VISION_STALE` | live_pid check_safety | 最新結果年齡 > `max_gap`（保存值 0.4 s，上限 0.5 s） |
| 車控已停 `VEHICLE_CONTROLLER_STOPPED`／`PHYSICAL_ESTOP` | live_pid check_safety | manual_drive 不再 busy |
| PID 輸入中斷 `BROWSER_INPUT_LOST` | manual_drive `_check` | PID 迴圈超過 1 s 沒送 `pid_input`（名稱是舊的，在 PID 模式下其實是「控制迴圈停了」，**跟瀏覽器無關**） |
| `UART_LOST`、`CAMERA_LOST` | manual_drive `_check` | 超過 1 s |
| 韌體回覆逾時 | manual_drive 非阻塞送出 | `ack_timeout_s`（uart_nonblock.json） |
| MCU 指令逾時 | 韌體 Config.h | `COMMAND_TIMEOUT_MS = 500`、`RX_FRAME_TIMEOUT_MS = 100` |
| 瀏覽器租約 `PID_BROWSER_LOST` | live_pid | **只在 `browser_lease` 模式**；`orin_timed` 不檢查 |

### 1.3 新模式的最小改法（提案，未實作）

- 新增 `execution_mode = 'orin_continuous'`，車端 status 回報能力 `continuous_version = 1`；07 只在看到這個能力時才用此模式，否則顯示「車端尚未支援持續行駛」，**不退回限時模式、不用極大秒數**。
- live_pid 與 manual_drive 兩層：此模式下 `deadline = None`，`seconds` 必須不存在（有值就拒絕，避免混用）；`check_safety` 與 `_check` 跳過到期判斷，其他判斷不變。

- 紀錄：目前一輪＝一個 `video_NNN.avi`（MJPG 10 fps）＋一個 `pid.jsonl`，**沒有輪替**。依 46db 估算每小時約影片 1.9 GB、pid.jsonl 0.6 GB、controls.jsonl 0.25 GB；Orin 剩 369 GB。單場數小時不會滿，但 pid.jsonl 是在控制迴圈裡同步寫入並 flush，長時間跑要另外確認寫入不會卡住控制迴圈。輪替可以之後再做，不是第一版的阻擋項目。

## 4. 優先項 3：跨圈對照與各路段接續

### 4.1 狀態語意（已核對程式）

**CurveMap（curve-map-r5）**
- `idx`＝「目前正在轉或下一個要轉」的彎在地圖清單中的位置。彎道開始（濾波後 gz < −12°/s，平地）建立 `cur`；結束（gz 回到 > −5°/s 持續 1.5 s 或離開平地）時，若轉過 > 30° 才 `idx+1`。
- 首圈 `seg=start`：清單 `[150, 210, 268]` → idx 0／1／2＝彎1／彎2／彎3。
- 每次 DashRoute 進入 DONE（下坡開始）：`seg=after_down`、`idx=0`，清單 `[180, 150, 210, 268]` → idx 0／1／2／3＝彎4／彎1／彎2／彎3。**第二圈以後彎1 是 after_down idx1，不是 idx0。**
- 彎內：`cur.yaw`（已轉角）、`cur.expected`、`cur.released`（ANGLE_DONE／INSIDE／FAR_OTHER_WAY／MAX_TIME）。`reason` 為 FLOOR 時才給轉速下限。
- 里程 `dist`：由車速（目前左輪）積分，每輪從 0 起算；地標在彎1結束後 9.45 m 預告彎2、下坡開始後 4.4 m 預告彎4。

**DashRoute（dash-route-r27）**
- WAIT_CLIMB →（俯仰 ≥ 8° 持續 2 s）CLIMBED →（< 3° 持續 0.5 s）OPEN →（俯仰 ≤ −5° **或 OPEN 已超過 60 s**）DONE →（曾 ≤ −10° 且回平 3 s）WAIT_CLIMB、`lap+1`。
- 「OPEN 超過 60 s 自動 DONE」是時間條件：若上段停車再接續時沿用舊的開啟時間，會誤判已下坡。接續時開啟時間必須重設。

**UpperPath（upper-path-r4）**
- 只在 OPEN 時運作；里程 `s` 以**MCU 編碼器累計值**相減（進入 OPEN 時記 `s0`），航向由進入時積分。控制板重啟後計數歸零，`s` 會錯。

**TrackPos（track-pos-r1，20:06 新增，只記錄）**
- 一圈座標 s：0＝下坡開始（DONE），一圈 66.8 m。錨點：DONE、CLIMBED（58.4）、OPEN（60.4）、地圖彎道開始在表上彎道起點 ±2.5 m 內且轉過 30°。
- 輸出 `segment`、`progress`、`next_curve`、`to_next_m`、`lap`（以 DONE 計，不是旗子）。
- 7 輪重播 51 個錨點誤差中位 0.26 m、P90 0.69 m、最大 1.51 m（依交接）。
- **這是 07 小地圖最直接可用的資料來源**，但只有 1 輪部署後資料，尚未實跑核對。
