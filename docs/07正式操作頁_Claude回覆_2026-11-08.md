## 0. 結論先講

1. **能完整跑圈的控制只有一套**：`camera-pair-v2-junction` 系列（V4＋雙邊界路徑＋DashRoute 坡道路線＋轉角地圖＋內迴路等規則層）。`-flag`／`-uphill`／`-crest-full` 是**同一套控制、起點路線狀態不同**，不是不同方案。獨立線估計 v1～v3、K 系列都是 10/29～10/30 的舊方案，之後相機姿態改過，沒有在現行跑道／相機下重新驗證，不建議放進 07。
2. **最後一次完整兩圈是 46db（11-08 17:0x）**。之後連續部署 10 批修正（curve-smooth r2/r3、fix3、arc-ff、arc-radius、curve-swing、cross-guard、upper-calm、down-bottom、arc-steady），**全部沒有實跑驗證**，期間 b559、c9f2、634e、cbfd、22af、9cad、cab7、f7c5、a065、bf69 都沒跑完。現役版本＝「最新但未驗證」。
3. **「方案」不是一個檔案**：一套方案＝筆電 PID 文件 revision＋Orin 約 30 個 json＋約 80 個 py＋舵機保存設定（rev29）＋韌體版本＋相機姿態。其中**一部分 json 是服務啟動後第一次用到才讀、之後整個程序都不再讀**，所以「換方案」實際上要換檔案並重啟車控（依 AGENTS.md 需另行授權）。07 不能只靠選單切換就切方案。
4. **前車偵測與測距：尚無。** V4 只有 background／boundary 兩類；車上沒有找到測距感測器的程式或韌體。「約 3 公尺」目前沒有任何可量測的來源。第一版建議標示「尚未開放」。
5. **任意路段接續：目前不支援。** 現行只能從三種起點開始（旗子平地、上坡、坡頂），而且路線狀態分散在 3 個以上互不相干的狀態機裡。要接續，最少需要「開始拆成準備／放行」「可帶入路線狀態的開始」「本場持久保存」三個新接口（見第 9 節）。

## 6. 路線狀態定義（已核對程式）

路線狀態**不是單一狀態機**，而是至少下列幾個獨立物件，每次 start 都重新建立：

| 物件 | 狀態 | 起始值 | 備註 |
| --- | --- | --- | --- |
| DashRoute（dash-route-r27） | WAIT_CLIMB → CLIMBED → OPEN → 虛線轉彎 → DONE；DONE 後回平 3 秒 → WAIT_CLIMB、`lap+1` | 旗子／上坡：WAIT_CLIMB；坡頂：OPEN | 只管坡道段；靠 IMU 俯仰 |
| CurveMap（curve-map-r5） | `seg`（start／after_down）、`idx`（第幾個彎）、`cur`（FLOOR／RELEASED／ANGLE_DONE）、`dist`（里程）、`odo`（下一個地標） | 永遠 seg=start、idx=0、dist=0 | 看到下坡開始才切 after_down |
| crossing_pass | 依 seg/idx 與「彎結束後里程」開窗；`_xp_ends` | 程序層級，跨輪保留 | 見第 4 節 |
| UpperPath（upper-path-r4） | 上段里程 `s`、航向 | 程序層級 | 進上段時以當時航向為零 |
| 其他 | DownhillEntry、BottomCommit、LaneSegment、HeadingHold、arc_radius 速度 EMA | 每輪新建 | 多數是短時間窗口 |

這些狀態已經寫在每格控制紀錄（pid.jsonl 的 proposal：dash 的 route／lap、curve_map 的 seg／idx／reason／dist_m／odo_to_m 等），可以從紀錄讀回「停止時在哪」，但**目前沒有任何方法把它們帶回新的一輪**。

## 8. 起跑準備、紅綠燈、故障對照

### 8.1 現行開始流程（已核對）
`start()` 一次做完：參數驗證 → 預覽一致性核對 → 選控制器 → 建立所有路線／控制物件 → 計算起跑回正等待 `start_hold_s`（依舵命令差與速度，最多約 1.5 秒）→ 開始送 PID。執行模式有 `browser_lease`（依賴心跳）與 `orin_timed`（Orin 自己計時）。**07 應使用 `orin_timed`**，避免筆電斷線就停車。

### 8.2 紅綠燈
- 車端**尚無**任何輪詢中控 `/go` 的程式。`camera-pair-v2-junction-flag` 只是起點名稱。
- 規劃文件第 6 節的行為（先看到 0 再接受 1、只放行一次、取消競態）我同意；實作前提是先完成第 9 節的「準備／放行」拆分，否則綠燈後還會有最多 1.5 秒回正等待，或必須提前讓 PID 跑起來。

### 8.3 故障與授權對照（依交接與程式）

| 代碼／訊息 | 意義 | 排除 |
| --- | --- | --- |
| `PCA_IO_FAILED`、`PCA_WRITE_FAILED` | 控制板 I²C 寫入失敗（舵機或馬達通道） | **BMduino 重新上電**；馬達通道（ch4/5）沒有重試，一次就故障 |
| `I2C_RETRY_READ_FAILED` | 舵機重試後讀回逾時（不可重試型態） | 同上 |
| `PHYSICAL_ESTOP` | 實體急停 | 解除後重新確認 |
| `BOOT_LOCK`／`LOCKED` | 開機鎖／鎖定，尚未允許起跑 | 走原後端授權流程 |
| `Check synchronized settings, ESTOP and web-start authorization` | 設定未同步、急停或網頁啟動授權不成立（FAULT 時也是這句） | 先看是否 FAULT |
| `PID limits exceed saved profile` | PID 上下限超出舵機保存範圍（例：min_us 750 < 780） | 維護端改 PID 文件 |
| `PID center must equal saved shared steering center` | PID 中心≠舵機保存中心 | 同步 |
| `Need 3 consecutive fresh valid model results` | 預覽沒有連續有效路徑 | 調整車位、重新載入 |
| `路徑算法與預覽不符`／`Restart preview with saved lookahead row`／`視覺中心已變更…` | 開始參數與預覽不一致 | 重新載入 |
| `PID_VISION_STALE`、`LOST_HEADING`、`LOST_TURN` | 行駛中影像過期或丟線停車 | 調整位置後人工接續 |
| `STALE_GENERATION` | 控制板代次已變（多見於重啟或測試收尾） | 重新確認車況 |
| `USER_STOP`、`PID_DURATION_COMPLETE` | 使用者停止、時間到 | — |

## 9. 三個重點回覆

### 9.1 從任意路段接續，最少要新增或拆開哪些接口？

1. **開始拆成「準備」與「放行」**：準備＝驗證、建立控制物件、回正、雙輪 0；放行＝開始送 PWM。紅綠燈與接續都需要它。
2. **開始時可帶入路線狀態（resume seed）**：至少包含
   - DashRoute：`state`、`lap`、`saw_down`；
   - CurveMap：`seg`、`idx`、已完成的彎、下一個里程地標（里程重新從 0 起算，地標距離改成「到下一彎還有多遠」的估計或直接停用該地標）；
   - crossing_pass：清除 `_xp_ends`，並依 seg/idx 決定是否還要開路口窗口；
   - UpperPath：只能在上段起點之前接續，上段中途接續先不支援（參考航向以進入時為零）；
   - 其餘短窗口（下坡入口、坡底、arc_radius EMA、PID 積分／微分、航向保持）一律重設。
   每個類別需要一個明確的 `seed()`，不能直接把舊物件還原。
3. **本場持久保存**：Orin 端一個本場檔（場次 ID、片段 run ID 清單、方案雜湊、最後路線摘要、計時事件），每秒或狀態改變時寫入。現有 pid.jsonl 已有每格路線資訊，可作為最後保存點的來源。
4. **程序層級快取在片段開始時重設**（第 4 節第一列）。

**不新增程式時目前可支援的起點：** 旗子平地、上坡（05～09 坡道）、坡頂。其他位置（彎1 之後、路口、藍色迴圈、大彎）直接開始會讓轉角地圖把下一個彎當成彎1，造成錯誤的半徑下限與路口窗口；arc-radius-r2 的 `IMPLAUSIBLE_START` 只擋掉一部分。

### 9.2 前車偵測與約 3 公尺測距有哪些能力？缺什麼？

- **偵測：尚無。** V4 只分白線；沒有前車模型、權重、標註資料或測試集。過去紀錄中曾出現前方紅色車（10/31、11/04 一次），只能當影像素材。
- **測距：尚無。** 本機韌體與 Orin 程式找不到測距感測器。單眼相機在目前姿態下沒有重新標定（只有「前輪最前緣到最近可見地面 27 cm」），3 公尺處在畫面很遠的上方，誤差未知。
- **缺的證據：** 前車在本車路線上的影像標註、測距來源（感測器或標定後的地面投影）、3 公尺處的實測誤差、遮擋／轉彎時的失效紀錄。
- **最小可行路線（需另行討論）：** (a) 加裝前向 ToF／超音波（硬體採購，最直接）；(b) 用錄影訓練車輛偵測＋相機重新標定估距（不需硬體，但 3 公尺單眼精度要先實驗）。07 第一版標示「尚未開放」。
